Performance & Tracing for Network Daemons

A link goes down at T0. Forwarding settles three seconds later, when it should have taken well under a tenth of a second. This guide is about finding where those seconds went: build a timeline, find the late stage, pick the lens that can see it, measure, fix, measure again.

Who this is for

Engineers who work on long-running, multi-threaded C daemons (routing stacks, control planes, anything with a pipeline of threads) and who have been told "convergence is slow" with nothing more to go on. You should know C and threads. You don't need to have used perf or eBPF before.

It is the sequel to Memory Debugging from First Principles, and reuses its approach: a fictional daemon, pktd; small labs that each plant one problem; and terminal output captured from real runs. That guide is about why a daemon crashes; this one is about why it's slow.

The one idea: slow convergence is as often waiting as computing. A CPU profiler only sees computing. Before you profile anything, find out which stage is late and whether that stage was on a CPU at all.

1. Where Time Goes

What you'll learn: the three things a thread can be doing at any instant, how to measure each one for a single thread, and why a CPU profiler is blind to two of them.

1.1 Three states

At any moment a thread is in one of three states, from the scheduler's point of view:

StateWhat it meansTypical cause in a daemon
On-CPU (running)Executing instructions, in user space or in the kernel on its behalfComputing, copying, parsing, a syscall's kernel work
Runnable (waiting to run)Ready to run, sitting in a CPU's run queue until the scheduler picks itMore ready threads than CPUs; a lower priority than its neighbours
Off-CPU (blocked)Asleep until something wakes itA mutex, a condition variable, a socket read, a timer, a page fault from disk

So, for any thread and any interval:

wall time = on-CPU time + run-queue wait + off-CPU (blocked) time

The kernel keeps the first two per thread in /proc/<pid>/task/<tid>/schedstat: nanoseconds on a CPU, nanoseconds waiting in a run queue, and the number of times it ran. Whatever is left of the wall time is time spent blocked.

1.2 One second, three ways

f1-where-time-goes starts seven threads. Six of them take about one second of wall time each and read their own schedstat just before they exit; the seventh only holds a mutex for lock to wait on.

  • spin burns one second of CPU.
  • sleep sleeps for one second.
  • lock waits for a mutex that the seventh thread holds for 900 ms, then works for 100 ms.
  • q0, q1 and q2 are pinned to the same CPU, and each needs a third of a second of CPU time.
sleep  wall  1000 ms = on-cpu     0 + runq-wait     0 + off-cpu  1000
lock   wall  1001 ms = on-cpu   100 + runq-wait     2 + off-cpu   899
spin   wall  1028 ms = on-cpu  1000 + runq-wait     5 + off-cpu    23
q0     wall  1037 ms = on-cpu   333 + runq-wait   682 + off-cpu    23
q1     wall  1036 ms = on-cpu   333 + runq-wait   683 + off-cpu    19
q2     wall  1036 ms = on-cpu   333 + runq-wait   685 + off-cpu    18
  1. sleep: about 1,000 ms of wall time and zero CPU. All of it was off-CPU.
  2. lock: 100 ms on a CPU and about 900 ms blocked on the mutex. A CPU profiler would show 100 ms of work and nothing else.
  3. q0–q2: 333 ms each on the CPU and about 680 ms each in the run queue. They were never blocked; they were ready the whole time and simply had to take turns.
  4. spin: on-CPU for the whole second.

All six threads took the same wall time. To a stopwatch they look alike, but they need three different fixes: less work, less waiting for others, or more CPU.

Deep dive: why the columns don't add up exactly

Wall time is measured from just after each thread starts, with CLOCK_MONOTONIC. schedstat counts from thread creation, with the scheduler's own clock. A thread's start-up and its final fopen of /proc land on one side but not the other, so the off-CPU column (wall minus the other two) absorbs a few tens of milliseconds of slack. The size of a gap is real; a 20 ms remainder is not.

1.3 The whole-process view: perf stat

perf stat runs a command and counts events for all its threads. With only software events it already answers one question: how many CPUs did this program keep busy, on average?

1.4 This is why

This is why a CPU profiler can't see lock waits or timers. perf record samples what is on a CPU. A blocked thread isn't on a CPU, so it produces no samples at all; a waiting thread is invisible, not small. The off-CPU tools in Ch 7 record the moment a thread leaves the CPU and the moment it returns, and charge the gap to where it left from. The run-queue tools in Ch 9 measure the gap between "woken" and "running".

2. Counting, Sampling, Tracing

What you'll learn: the three ways a tool can observe a program, what each costs, and how a sample turns into a stack, including when a frame goes missing.

2.1 Three ways to observe

ModeWhat it recordsCostAnswersIn this guide
CountingA total per event: cycles, instructions, context switchesNear zero: the CPU or kernel keeps a counterHow much? How efficient?perf stat, schedstat
SamplingEvery Nth event, or N times a second: the instruction pointer and a stackProportional to the sample rate, not to the program's activityWhere is CPU time going?perf record, flame graphs
TracingEvery occurrence of an event, with a timestamp and argumentsProportional to how often the event firesWhen? How long did each one take? In what order?bpftrace, perf trace, USDT, tracepoints

Counting is where you start: it's cheap and tells you whether to look further. Sampling finds hot code. Tracing finds latency: a single 300 ms lock wait is one event, and a sampler running at 999 Hz might not land on the waiting thread even once, because the thread isn't running.

Observer effect. Tracing an event that fires 50,000 times a second adds the probe's cost 50,000 times. A bpftrace probe costs on the order of a microsecond; strace costs far more, because it stops the process twice per syscall. Prefer aggregating in the kernel (counts and histograms) to printing every event.

2.2 How a sample becomes a stack

When the sampling interrupt fires, the kernel records the interrupted instruction pointer, then walks the stack to find the callers. There are three ways to do the walk:

MethodHowNeedsFails when
Frame pointers (-g, the default)Follow the chain of saved %rbp values; each frame stores the caller's return address next to itCode built with -fno-omit-frame-pointerAny function on the stack was built without frame pointers (often libc), or hasn't set up its frame yet
DWARF (--call-graph dwarf)Copy a chunk of the user stack with every sample, then unwind it afterwards using the debug info's unwind tablesDebug info (-g) or .eh_frameThe stack is deeper than the copy (8 KiB by default). The cost is much larger perf.data files
LBR (--call-graph lbr)The CPU's Last Branch Record hardware keeps recent calls and returnsAn Intel CPU, with LBR passed through to the VMThe stack is deeper than the LBR (16–32 entries); often unavailable in VMs

The labs build with -O2 -g -fno-omit-frame-pointer -fno-optimize-sibling-calls. The last flag stops the compiler turning a call in tail position into a jump: after such a jump, the caller's frame is gone and it disappears from every stack beneath it.

Deep dive: why the sample rate is 999, not 1000

Daemons often have timers at round frequencies: 10 ms ticks, 1 ms polls. Sampling at exactly 1000 Hz can fall into lockstep with that activity and always see the same phase of it. An odd rate such as 999 (or 99, for long runs) drifts against round periods and samples every phase evenly.

2.3 This is why

This is why the labs build with frame pointers, and why a frame can still go missing. Frame-pointer unwinding is cheap enough to leave on all the time, but it trusts every function on the stack to have saved %rbp. At -O2, GCC still gives leaf functions (functions that call nothing) no frame of their own. A sample inside a leaf therefore skips straight from the leaf to its caller's caller. GCC has -mno-omit-leaf-frame-pointer for exactly this, but Debian 12's GCC 12 still emitted frameless leaves with it in the lab's test, so check your compiler's output with objdump -d before relying on it. 3. Under the Hood: perf_event & eBPF

What you'll learn: the one kernel interface behind perf, bpftrace and rr; the kinds of events it can attach to; and why each docker run flag in this kit exists.

3.1 perf_event_open: one syscall, many event types

Every tool in this guide, and rr from the prequel, starts with the same syscall: perf_event_open. It creates a counter or a sampler for one thread, one process or one CPU. You choose an event, and the kernel either counts it or writes samples into a ring buffer the tool reads.

Event sourceExamplesWhere it comes from

Softwaretask-clock, context-switches, page-faultsCounters the kernel keeps itself; always available
Tracepointssched:sched_switch, syscalls:sys_enter_writeFixed hooks compiled into the kernel, with a stable format in tracefs

3.2 eBPF: running your code at the event

Counting and sampling are built in. eBPF lets you attach your own small program to any of these events, inside the kernel:

  • The verifier checks the program before it loads: bounded loops, checked memory access, no crashes. That check is what makes it acceptable to run your code in the kernel.
  • Maps are key/value stores shared between the in-kernel program and the tool. Counting and histograms happen in the kernel, and only the totals cross to user space. That's why a bpftrace histogram over 24,000 events is cheap.
  • Helpers give the program the time (nsecs), the current thread (tid, comm) and a stack id (ustack, kstack).
  • BTF is compact type information for the running kernel, at /sys/kernel/btf/vmlinux. With it, bpftrace can read kernel structs without kernel headers.

bpftrace is a small language that compiles to eBPF. This guide uses it for everything that needs timing between two events: lock waits, off-CPU time, run-queue latency, stage timings from USDT.

3.3 Permissions, and why the container needs its flags

/proc/sys/kernel/perf_event_paranoid decides what an unprivileged user may observe. At 2 (the upstream default) a user can profile their own processes in user space. Debian and some other distributions add a level 3, which forbids perf_event_open to unprivileged users altogether. The capture host ran at 3.

FlagWhy the labs need it
--cap-add SYS_ADMINAt paranoid 3, only CAP_SYS_ADMIN may open perf events. It also covers bpf(), and Docker's default seccomp profile allows both syscalls once the container has it, so seccomp needs no change. On hosts at paranoid ≤ 2, CAP_PERFMON + CAP_BPF are enough
-v /sys/kernel/tracing:…:roTracepoint formats and IDs live in tracefs, which a container doesn't mount. Read-only is enough
--cap-add SYSLOGLets perf read kernel symbol addresses from /proc/kallsyms, so kernel frames get names. This works when the host's kptr_restrict is 0 or 1; at 2, kernel frames stay unnamed

These flags reach the host kernel. A probe loaded from the container runs in the one kernel every tenant shares, and a tracepoint fires for every thread on the machine. The labs therefore attach perf only to their own commands, put uprobes only on their own binaries, filter tracepoints to their own container's cgroup and threads named pktd-*, and arm everything between their own USDT probes. Shared-Host Rules has the full list.

3.4 Two container surprises

  • PID namespaces. Inside the container a process might be PID 12; the kernel, and so every eBPF program, knows it by its host PID. bpftrace names user-space frames by reading /proc/<pid>/maps for the host PID, which doesn't exist in the container's /proc, so every frame prints as [unknown]. The labs save their own memory map (PKTD_MAPS=<file>) and symbolize.py names the frames with addr2line. The same mismatch is why bcc tools' -p PID option doesn't help inside a container.
  • perf's version tracks the kernel's. perf ships with the kernel source, and distributions package it per kernel version. The lab image is Debian 12 because its perf 6.1 matches the host's 6.1 kernel.

3.5 This is why

This is why every probe in the labs is scoped. A uprobe on pthread_mutex_lock in libc would put a breakpoint into every process on the host that uses libc. The labs instead probe rib_lock_acquire, a wrapper that exists only in their own binary. A sched_switch tracepoint fires for every thread on the host, so it filters in the kernel, before any work is done: on the container's own cgroup (cgroup == cgroupid("/sys/fs/cgroup"); inside a container with cgroup v2 that path is the container's cgroup) and on the pktd- thread names. One subtlety: cgroup is the cgroup of whichever task is running when the event fires. For a sched_switch that is the outgoing task, and a wake-up can fire from an interrupt in anyone's context. So the scripts check the cgroup where the current task is theirs, note those thread ids, and match wake-ups and switch-ins against that list.

4. Reading Flame Graphs

What you'll learn: what width and height mean, the three misreadings everyone makes once, and the pipeline from perf record to the picture.

4.1 From samples to folded stacks

A flame graph starts as folded stacks: one line per distinct stack, outermost frame first, frames separated by ;, then the number of samples with that exact stack. The lab kit makes them with fold-perf.awk:

perf record -F 999 -g -o /tmp/p.data ./01-hot-path --fixed
perf script -i /tmp/p.data -F comm,ip,sym | awk -f fold-perf.awk

The lines for the two SPF functions (| grep ';spf_' on the same pipeline). The first field is the thread name:

pktd-ctl;__libc_start_call_main;main;pipeline_main.constprop.0;spf_extract_min 14
pktd-ctl;__libc_start_call_main;main;pipeline_main.constprop.0;spf_relax 18
pktd-spf;start_thread;spf_main;compute_routes;spf_extract_min 17
pktd-spf;start_thread;spf_main;compute_routes;spf_relax 26
  1. The pktd-ctl lines: the main thread's start-up SPF, before the event. Profiling the whole run includes set-up as well as the work you care about.
  2. The pktd-spf lines: the measured event's SPF: a few dozen samples between spf_extract_min and spf_relax.

4.2 The picture

Each box is a function in a stack. The bottom row is the root, and each row above is called by the one beneath it. Width is the share of samples that had that function on the stack.

  • Width = how much, not when. The x-axis is sorted alphabetically within each parent, so left-to-right order means nothing about time.
  • Look at the top edges. A wide box with nothing on top of it is a function spending its own time (a "plateau"). A wide box covered by its children is just a caller.
  • Colours are random. Here they're picked by a hash of the name so a function keeps its colour across graphs. They don't encode anything.
  • An on-CPU graph has no idle. A thread that waited for 300 ms contributes nothing. A narrow graph doesn't mean a fast program.

4.3 Off-CPU flame graphs

Same picture, different weights: each stack is weighted by the microseconds the thread spent blocked with that stack, not by samples. You build one by tracing, because there is nothing to sample while a thread is asleep: record when a thread goes to sleep and where from, record when it is woken, and add up the difference by stack. Ch 7 does exactly that with a short bpftrace script.

Off-CPU graphs include idle by design. A worker waiting for work and a worker stuck behind a lock look alike: both are blocked. Restrict the graph to the window that matters (the labs arm their probes at the event and stop at convergence) and read the threads on the critical path first.

4.4 This is why

This is why the guide always pairs a flame graph with the timeline. A flame graph tells you where the samples went; it can't tell you whether those samples are what delayed convergence. The timeline (Ch 5) names the late stage first; the flame graph then explains that stage.

5. The Convergence Timeline

What you'll learn: how to turn "convergence is slow" into a per-stage latency budget, how to get the same timeline from outside the program with USDT probes, and how to pick the lens for the stage that's late.

Builds on: the three thread states (Ch 1) and USDT probes (Ch 3).

5.1 Stamp every stage

A convergence event crosses threads, so no single thread's profile covers it. What does cover it is a timestamp at the start and end of each stage, taken against one clock, relative to the event. pipeline.h does this with two helpers:

enum stage { ST_HOLD, ST_COMPUTE, ST_RIB, ST_PUSH, ST_N };
static const char *stage_name[ST_N] = { "hold", "compute", "rib", "push" };
⋯
static void tl_begin(enum stage s) { st_begin[s] = now_ns(); DTRACE_PROBE2(pktd, stage, s, 1); }
static void tl_end(enum stage s)   { st_end[s] = now_ns();   DTRACE_PROBE2(pktd, stage, s, 0); }

The SPF thread runs three stages back to back, each between a tl_begin and a tl_end:

  tl_begin(ST_HOLD);
  throttle_wait();
  tl_end(ST_HOLD);

  tl_begin(ST_COMPUTE);
  if (C.cli_walk) {
    pthread_mutex_lock(&walk_mu);
    walk_go = 1;
    pthread_cond_signal(&walk_cv);
    pthread_mutex_unlock(&walk_mu);
  }
  compute_routes();
  tl_end(ST_COMPUTE);

  tl_begin(ST_RIB);
  rib_update();
  tl_end(ST_RIB);
  • CLOCK_MONOTONIC, never wall-clock time: NTP can step the wall clock in the middle of an event.
  • Every stamp also fires a USDT probe. Disabled, a USDT probe is a single nop. Enabled, a tracer sees the same boundaries without the program printing anything (5.3).
  • The gaps between stages count too. The time between one stage's end and the next stage's begin, on another thread, is a hand-off: a condition-variable wake-up and a trip through the scheduler. The budget reports it as handoff.

5.3 The same timeline from outside

You won't always be able to rebuild a daemon with print statements. If the stage boundaries are USDT probes, a tracer can rebuild the timeline from outside. bt/stages.bt attaches to the four probes in the lab binary (the binary's path is $1):

bt/stages.bt
// stages.bt — the convergence timeline from pktd's USDT probes, with no help from the program.
//   bpftrace -c ./00-baseline bt/stages.bt ./00-baseline        ($1 = the lab binary)
// USDT probes live in the binary, so this traces only that program.

BEGIN { @name[0] = "hold"; @name[1] = "compute"; @name[2] = "rib"; @name[3] = "push"; }

usdt:$1:pktd:event { @t0 = nsecs; printf("T+%8d us  event\n", 0); }

usdt:$1:pktd:stage /arg1 == 1/ {
  @begin[arg0] = nsecs;
  printf("T+%8d us  %-8s begin\n", (nsecs - @t0) / 1000, @name[arg0]);
}

usdt:$1:pktd:stage /arg1 == 0/ {
  printf("T+%8d us  %-8s end    took %d us\n", (nsecs - @t0) / 1000, @name[arg0],
         (nsecs - @begin[arg0]) / 1000);
}

usdt:$1:pktd:converged { printf("T+%8d us  converged\n", (nsecs - @t0) / 1000); exit(); }

END { clear(@name); clear(@begin); delete(@t0); }

5.4 From budget to lens

1
Find the stage that owns the most time

Read the budget. Ignore anything under about 10%. If one stage owns more than half, start there. If two are close, start with the larger one, and expect fixing it to change the other (Ch 11).

2
Ask whether its thread was on a CPU

Compare the stage's wall time with the thread's CPU time over the same window (perf stat per thread, schedstat, or an on-CPU profile). Close to equal: the thread was computing. Far less: it was waiting.

3
If it waited, find out for what

Blocked on a lock or a socket: off-CPU stacks. Ready but not running: run-queue latency. Asleep on purpose: a timer, which shows on the timeline as a gap with nothing running.

4
Fix one thing, then re-run the timeline

The budget after a fix is the only proof that the fix was the right one. It's also where a second problem that the first one was hiding shows up.

5.5 This is why

This is why every rung starts from the timeline, not from a profiler. A profile of the whole daemon shows where CPU went across every thread and every phase, including set-up and idle loops. The timeline narrows the question to one stage on one thread in one window, and only then is a profile, a trace or a histogram worth reading.

6.4 The missing frame

Both hot functions are leaves: they call nothing. GCC at -O2 doesn't set up a frame pointer in a leaf, even with -fno-omit-frame-pointer. When a sample lands inside one, %rbp still points at spf_run's frame, and that frame holds spf_run's return address, which is in compute_routes. The walk goes straight from the leaf to compute_routes, and spf_run vanishes (Ch 2).

DWARF unwinding uses the compiler's unwind tables instead of %rbp, so it doesn't depend on what a function did with its frame:

6.5 Why it's slow, and the fix

/* Bug 01 lives here: one SPF per change instead of one SPF for the whole event. */
NOINLINE static void compute_routes(void) {
  for (int i = 0; i < C.changes; i++) {
    apply_change(i);
    if (C.spf_per_change) spf_run();
  }
  if (!C.spf_per_change) spf_run();
}

The event carries 64 link changes. The slow path runs a full O(N²) SPF after each one, 64 SPFs where one would do: the last SPF sees every change anyway. Throttles exist partly to batch changes like this; this code batches them and then throws the batching away. --fixed applies all the changes, then runs SPF once.

Deep dive: when the plateau is a memory stall

Here IPC was about 1.4, so the loops were limited by how much work they do. 7.3 Off-CPU: where each thread waited

bt/offcpu.bt traces sched_switch. When a pktd- thread in this container goes to sleep, it records the time and the user stack; when that thread is woken, it charges the gap to that stack. A thread that is preempted is not asleep, so it isn't counted: its wait is run-queue time (Ch 9). It is armed by the lab's own pktd:event probe and exits at pktd:converged.

bt/offcpu.bt
// offcpu.bt — blocked (off-CPU) time by thread and user stack, between the event and convergence.
//   PKTD_MAPS=/tmp/maps bpftrace -c ./02-lock bt/offcpu.bt ./02-lock     ($1 = the lab binary)
// Blocked time runs from the switch-out to the wake-up: the run-queue wait after the wake-up is
// runqlat.bt's, not this script's.
// Scope: sched tracepoints fire for every thread on the host. A switch-out runs in the outgoing
// task, so `cgroup` identifies it: only pktd- threads in this container's cgroup are recorded,
// and wake-ups are matched against those thread ids. Armed by pktd's own USDT probes; exits at
// convergence. Output is microseconds per (thread, stack); symbolize.py names the frames
// (PKTD_MAPS saves the lab's memory map for it) and fold-bt.awk turns it into folded stacks.

usdt:$1:pktd:event { @armed = 1; }
usdt:$1:pktd:converged { exit(); }

// Going to sleep: remember when, and where in user space. A thread switched out while still
// runnable (prev_state 0, or 0x100 for a preemption inside the kernel) isn't blocked.
tracepoint:sched:sched_switch
/@armed && cgroup == cgroupid("/sys/fs/cgroup") && strncmp(args->prev_comm, "pktd-", 5) == 0 &&
 args->prev_state != 0 && args->prev_state != 0x100/ {
  @start[args->prev_pid] = nsecs;
  @stack[args->prev_pid] = ustack(perf);
  @name[args->prev_pid] = args->prev_comm;
}

// Woken: charge the blocked time to the stack it went to sleep from.
tracepoint:sched:sched_wakeup /@start[args->pid]/ {
  @offcpu_us[@name[args->pid], @stack[args->pid]] = sum((nsecs - @start[args->pid]) / 1000);
  delete(@start[args->pid]);
  delete(@stack[args->pid]);
  delete(@name[args->pid]);
}

END { clear(@start); clear(@stack); clear(@name); delete(@armed); }

  • pktd-cli → cli_show_rib → write: the CLI thread spent its time blocked in write. Its reader is slow, so the pipe is full.
  • pktd-term → clock_nanosleep: the slow reader, sleeping between reads.
  • pktd-ctl and pktd-push in __futex_abstimed_wait_common64: idle by design. The main thread is waiting to join; the push thread is waiting for the RIB. Ch 4 warned about these.
Frames are missing again. rib_update calls rib_lock_acquire, which calls pthread_mutex_lock, which waits in futex_wait. Debian 12's libc is built without frame pointers, so the walk loses the frames between the libc function and the first frame of ours that it finds. Read rib_update → futex_wait as "somewhere under rib_update, in a futex wait".

7.4 Who holds the lock?

An off-CPU stack names the waiter. To name the holder, time the lock itself. bt/lock-wait.bt puts uprobes on rib_lock_acquire and rib_lock_release, small wrappers that exist only in this binary, and measures how long each thread waited for the lock (by thread) and how long it held it (by thread and stack):

// The uprobes sit on pktd's own wrappers (rib_lock_acquire / rib_lock_release), which exist only

7.5 Why it's slow, and the fix

/* Bug 02 lives here: holding rib_lock while writing to a slow reader. */
NOINLINE static void cli_show_rib(void) {
  if (C.walk_holds_lock) {
    rib_lock_acquire();
    cli_format_and_write(rib, R);
    rib_lock_release();
  } else {
    struct route *snap = malloc(R * sizeof *snap);
    rib_lock_acquire();
    memcpy(snap, rib, R * sizeof *snap);
    rib_lock_release();
    cli_format_and_write(snap, R);
    free(snap);
  }
}

An operator's show rib walks the RIB and writes each route to a terminal while holding rib_lock. The terminal is slow, so the walk takes as long as the terminal takes to drain 24,000 lines, and every RIB update waits behind it. The fix: copy the RIB under the lock (a memcpy of 384 kB, well under a millisecond), drop the lock, then format and write the copy.

8.4 Why it's slow, and the fix

/* Bug 03 lives here: batch == 1 means one message and one ack per route. */
NOINLINE static void push_routes(void) {
  int batch = C.stop_and_wait ? 1 : BATCH;
  uint32_t ack;
  for (int i = 0; i < R; i += batch) {
    int n = R - i < batch ? R - i : batch;
    if (write(fib_fd[0], &rib[i], (size_t)n * sizeof *rib) < 0) { perror("push write"); exit(1); }
    if (read(fib_fd[0], &ack, sizeof ack) != sizeof ack) { perror("push ack"); exit(1); }
  }
}

With batch == 1, each route costs a write, a wake-up of the FIB thread, its read, its write of the ack, a wake-up of the push thread, and the push thread's read. The two wake-ups, with their trips through the scheduler, cost more than the syscalls themselves. --fixed sends 512 routes per message, still with one ack per message:

Deep dive: strace -c vs perf trace -s

strace uses ptrace: the kernel stops the traced thread at every syscall entry and at every exit, switches to strace, which reads the registers, and switches back. That's about four extra context switches per syscall, eight per route here, and it can slow a syscall-heavy stage several-fold while you measure it. perf trace reads the same events from tracepoints into a ring buffer without stopping anything. Use strace when you need decoded arguments for a few calls, and perf trace or bpftrace to count.

9.5 Why it's slow, and the fix

Three things combine. The process is confined to 2 CPUs, as in a container with a CPU limit. It runs 8 I/O poller threads that spin on a flag. And someone set the pipeline threads to nice 10 "to protect the pollers":

/* Lab 04: someone lowered the pipeline threads' priority "to protect the I/O pollers".
 * On Linux, setpriority() on a thread id changes just that thread. Raising nice needs no privilege. */
static void set_nice(void) {
  if (C.pipeline_nice) setpriority(PRIO_PROCESS, (id_t)gettid(), C.pipeline_nice);
}
⋯
/* Bug 04 lives here: spinning on a flag instead of sleeping until there is work. */
NOINLINE static void io_poll_once(void) {
  if (C.poll_busy) {
    for (int i = 0; i < 1000 && !atomic_load(&io_ready); i++) __asm__ volatile("pause");
  } else {
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    ts.tv_nsec += 10000000;
    if (ts.tv_nsec >= 1000000000) { ts.tv_sec++; ts.tv_nsec -= 1000000000; }
    pthread_mutex_lock(&io_mu);
    if (!atomic_load(&io_ready) && !atomic_load(&stop_all)) pthread_cond_timedwait(&io_cv, &io_mu, &ts);
    pthread_mutex_unlock(&io_mu);
  }
}
  • The Linux scheduler gives each runnable thread a share of the CPU in proportion to its weight. Nice 0 weighs 1024; nice 10 weighs 110. With eight pollers always runnable at weight 1024, a nice-10 thread's fair share is about 1/75th of the two CPUs. The scheduler gives a thread that has just woken up a little credit, so it does somewhat better than that, but its 10 ms of work still stretched to well over 100 ms.
  • Spinning pollers are always runnable, so the queue is never empty. Pollers that sleep until there is work leave the CPUs free whenever there's none.

static void throttle_history(void) {
  /* The link flapped C.flaps times ten minutes ago; each flap doubled the hold. */
  for (int i = 0; i < C.flaps; i++) thr_hold_ms = thr_hold_ms * 2 > HOLD_MAX_MS ? HOLD_MAX_MS : thr_hold_ms * 2;
  thr_last_ns = now_ns() - 600ull * 1000000000ull;
}

/* Bug 05 lives here: the backoff never resets after the network goes quiet. */
NOINLINE static void throttle_wait(void) {
  uint64_t t = now_ns();
  if (C.hold_reset && t - thr_last_ns > QUIET_RESET_S * 1000000000ull) thr_hold_ms = HOLD_INIT_MS;
  thr_last_ns = t;
  int hold = thr_hold_ms;
  DTRACE_PROBE1(pktd, hold, hold);
  struct timespec ts = { hold / 1000, (long)(hold % 1000) * 1000000L };
  clock_nanosleep(CLOCK_MONOTONIC, 0, &ts, NULL);
  thr_hold_ms = hold * 2 > HOLD_MAX_MS ? HOLD_MAX_MS : hold * 2;
}

Exponential backoff is right during a flap storm: it stops the daemon recomputing on every flap. But the backoff has to decay. Here nothing ever brings the hold back down, so a network that flapped ten minutes ago still waits 64 times the initial hold now. --fixed resets the hold to its initial value after 30 seconds of quiet. That's the usual shape of SPF and LSP-generation throttles: initial wait, increment, maximum, and a quiet period that resets them.

12. Applying It to Your Daemon

What you'll learn: what to add to a real daemon so the next "convergence is slow" takes minutes, what to measure first, and how to keep convergence time from regressing. No captures here: this chapter is about your code, not the lab's.

12.1 Make the stages visible

The labs could be diagnosed quickly because every stage had a begin and end stamp and a USDT probe. Most daemons have neither. Adding them is a small change:

#include <sys/sdt.h>          /* systemtap-sdt-dev / systemtap-sdt-devel: a header, no library */

DTRACE_PROBE1(mydaemon, event, event_id);          /* something changed: T0 */
DTRACE_PROBE2(mydaemon, stage, STAGE_SPF, 1);      /* stage begin */
DTRACE_PROBE2(mydaemon, stage, STAGE_SPF, 0);      /* stage end */
DTRACE_PROBE1(mydaemon, converged, event_id);      /* the last FIB ack */
  • Pick stage boundaries at thread hand-offs. That's where queueing hides, and where the labs' handoff line came from.
  • Carry an event id through the pipeline if events overlap, so a tracer can join begin and end of the same event across threads.
  • Expose every timer's current value: throttles, hold-downs, backoffs, delays. A probe argument or a counter in a show command. Ch 10 is what happens without it.
  • Wrap the locks on the convergence path in small functions of your own, so you can uprobe them without probing libc (Ch 7).
  • Disabled USDT probes cost a nop. If computing an argument is expensive, guard it with the probe's semaphore (DTRACE_PROBE*_ENABLED-style macros, or STAP_PROBE with semaphores), so the work only happens while a tracer is attached.

12.2 What to measure first

1
Get the timeline for one slow event

From the USDT probes, logs with monotonic timestamps, or (if there's nothing else) timestamps on the protocol messages entering and FIB updates leaving.

2
Get per-thread CPU time over the same window

/proc/<pid>/task/*/schedstat before and after: on-CPU and run-queue time per thread, and the rest of the wall time is blocked. That splits the late stage into computing, queued and blocked. (perf stat --per-thread -p <pid> gives the CPU time only.)

3
Pick the lens from the matrix

Decision Matrix. Attach to the running daemon (-p), never system-wide on a shared machine, and arm tracing only around the event.

4
Fix the biggest share; repeat

And keep the timeline from each run: it's the evidence for the fix.

12.4 Keep it from coming back

  • Build with frame pointers. It costs a percent or two at most, and turns every on-CPU and off-CPU stack from guesswork into something you can read. Several distributions now build their packages, libc included, with frame pointers for exactly this reason.
  • Gate on convergence time in CI. A lab-sized topology, a scripted flap, the USDT timeline, and a threshold per stage. A test that fails when compute doubles catches Ch 6 before it ships.
  • Continuous profiling (sampling every host at a low rate, all the time) gives you the on-CPU picture from before a regression as well as after. It won't see waiting; keep the timeline for that.
  • Review checklist for code on the convergence path: no I/O under a convergence lock; batching across a thread boundary; every timer decays and is visible; no busy-polling threads sharing CPUs with it; no lowered priority on it.

## Shared hosts: the rules these labs follow

These capabilities let the container load programs into the **host's** kernel. On a host you
share, keep every probe scoped to your own processes:

- No system-wide `perf` (`-a`, `perf sched record`, `perf top`): attach to a command or a PID.
- bpftrace: USDT probes and uprobes on your own binary only. A uprobe on a shared library such as
  libc traps in every process on the host that uses it.
- Tracepoints and kprobes fire for every thread on the host, so filter in the probe and arm them
  only between the lab's own USDT probes. These labs filter on the container's own cgroup
  (`cgroup == cgroupid("/sys/fs/cgroup")`: inside a container with cgroup v2, that path is the
  container's cgroup) and on the `pktd-` thread names. The cgroup filter is what keeps someone
  else's run of the same labs, on the same host, out of your histograms; a PID filter would need
  the host's PID, which the container doesn't know.
- Every run is bounded: the scripts exit at `pktd:converged`, and `run-capture.sh` adds a timeout.
- bcc tools (`offcputime`, `runqlat`, …) take a PID, but inside a container the PID you know is not
  the one the kernel sees; without a usable filter they trace the whole host, so these labs don't
  use them. `probe.sh` checks `perf lock contention`'s BPF mode from its help text rather than
  running it, for the same reason.

## Why `symbolize.py` exists

bpftrace resolves a user-space address by reading `/proc/<pid>/maps` of the traced process. In a
container it only knows the host's PID for that process, which does not exist in the container's
`/proc`, so every frame prints as `[unknown]`. The pipeline labs save their own memory map when
`PKTD_MAPS=<file>` is set; `symbolize.py` uses it and `addr2line` to name each frame.
`--pid=host` would also fix it, but it shows the container every process on the host.

## Caveats

- **x86-64 Linux only.** The captures come from a 16-vCPU KVM guest with a virtual PMU and a

  instructions; use `-e cpu-clock` for sampling.
- **`perf lock contention -b`** needs a `perf` built with BPF skeletons; Debian 12's isn't, so

- **Files made by the container are root-owned on a Linux host.** `remote.sh` fixes that; by hand:

pipeline.h
/* pipeline.h — pktd's route pipeline (fictional, illustrative; not taken from any real daemon).
 *
 * One convergence event flows through four stages, each on its own thread:
 *
 *   control (pktd-ctl)  injects a link change at T0
 *   hold    (pktd-spf)  SPF throttle: wait before computing
 *   compute (pktd-spf)  shortest-path first over the topology
 *   rib     (pktd-spf)  write every route into the shared RIB under rib_lock
 *   push    (pktd-push) send the routes to the FIB thread (pktd-fib) and wait for acks
 *
 * "Converged" is the moment the last FIB ack arrives. Every stage stamps CLOCK_MONOTONIC and
 * fires a USDT probe, and pipeline_main() prints the timeline and a per-stage budget at exit.
 *
 * Each lab sets a struct cfg that plants one slowdown (or several, for the boss level);
 * --fixed (or --fix=... for the boss) selects the fix. Build: see the Makefile.
 */

#include <errno.h>
#include <pthread.h>

#include <stdint.h>
#include <stdio.h>

/* ---------- configuration: what each lab plants ---------- */
struct cfg {
  const char *lab;
  int fixed;           /* labs 01-05: 1 = the fixed variant */
  int nodes;           /* topology size */
  int changes;         /* link changes in the event */
  int spf_per_change;  /* bug 01: run a full SPF for every change instead of once */
  int cli_walk;        /* a "show rib" walker starts when compute begins */
  int walk_holds_lock; /* bug 02: the walker formats and writes while holding rib_lock */
  int stop_and_wait;   /* bug 03: push one route per message, wait for one ack each */
  int pollers;         /* number of I/O poller threads */
  int poll_busy;       /* bug 04: pollers spin instead of sleeping */
  int cpus;            /* pin the process to this many CPUs (0 = no pinning) */
  int flaps;           /* bug 05: earlier flaps already in the throttle's history */
  int hold_reset;      /* fix 05: reset the backoff after a quiet period */
  int schedstat;       /* print per-thread schedstat at exit */
  int pipeline_nice;   /* bug 04: nice value of the pipeline threads (spf, push, fib) */
};

#define PREFIXES_PER_NODE 16
#define BATCH 512
#define HOLD_INIT_MS 50
#define HOLD_MAX_MS 10000
#define QUIET_RESET_S 30

/* ---------- the timeline ---------- */
enum stage { ST_HOLD, ST_COMPUTE, ST_RIB, ST_PUSH, ST_N };
static const char *stage_name[ST_N] = { "hold", "compute", "rib", "push" };
static uint64_t t0_ns, st_begin[ST_N], st_end[ST_N];

static uint64_t now_ns(void) {
  struct timespec ts;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  return (uint64_t)ts.tv_sec * 1000000000ull + (uint64_t)ts.tv_nsec;
}
static void tl_begin(enum stage s) { st_begin[s] = now_ns(); DTRACE_PROBE2(pktd, stage, s, 1); }
static void tl_end(enum stage s)   { st_end[s] = now_ns();   DTRACE_PROBE2(pktd, stage, s, 0); }
static double ms(uint64_t a, uint64_t b) { return (double)(b - a) / 1e6; }

/* ---------- topology, SPF, RIB ---------- */
struct route { uint32_t prefix; uint32_t nexthop; uint32_t metric; uint32_t flags; };

static struct cfg C;
static int N, R;
static uint16_t *w;                 /* N x N link weights, 0 = no link */
static uint32_t *dist, *firsthop;
static struct route *rib;
static pthread_mutex_t rib_lock = PTHREAD_MUTEX_INITIALIZER;

static uint32_t rnd_state = 12345;
static uint32_t rnd(void) { rnd_state = rnd_state * 1103515245u + 12345u; return rnd_state >> 8; }

static void topo_build(void) {
  w = calloc((size_t)N * N, sizeof *w);
  dist = malloc(N * sizeof *dist);
  firsthop = malloc(N * sizeof *firsthop);
  rib = calloc(R, sizeof *rib);
  for (int u = 0; u < N; u++)
    for (int k = 0; k < 4; k++) {
      int v = (int)(rnd() % N);
      if (v == u) continue;
      w[u * N + v] = w[v * N + u] = (uint16_t)(1 + rnd() % 20);
    }
  for (int i = 0; i < R; i++) rib[i].prefix = 0x0a000000u | (uint32_t)i << 8;
}

/* Lock wrappers live in the binary, so a uprobe on them traces only this program. */
NOINLINE void rib_lock_acquire(void) { pthread_mutex_lock(&rib_lock); }
NOINLINE void rib_lock_release(void) { pthread_mutex_unlock(&rib_lock); }

NOINLINE static int spf_extract_min(const uint8_t *done) {
  int best = -1;
  uint32_t bd = UINT32_MAX;
  for (int v = 0; v < N; v++)
    if (!done[v] && dist[v] < bd) { bd = dist[v]; best = v; }
  return best;
}

NOINLINE static void spf_relax(int u, uint32_t *parent) {
  const uint16_t *row = &w[(size_t)u * N];
  for (int v = 0; v < N; v++)
    if (row[v] && dist[u] + row[v] < dist[v]) { dist[v] = dist[u] + row[v]; parent[v] = (uint32_t)u; }
}

/* O(N^2) Dijkstra from node 0: fine once, expensive when repeated. */
NOINLINE static void spf_run(void) {
  uint8_t *done = calloc(N, 1);
  uint32_t *parent = malloc(N * sizeof *parent);
  for (int v = 0; v < N; v++) { dist[v] = UINT32_MAX; parent[v] = UINT32_MAX; }
  dist[0] = 0;
  for (int i = 0; i < N; i++) {
    int u = spf_extract_min(done);
    if (u < 0) break;
    done[u] = 1;
    firsthop[u] = (u == 0) ? 0 : (parent[u] == 0 ? (uint32_t)u : firsthop[parent[u]]);
    spf_relax(u, parent);
  }
  free(done);
  free(parent);
}

static int changed_u[256], changed_v[256];

NOINLINE static void apply_change(int i) {
  int u = changed_u[i], v = changed_v[i];
  w[u * N + v] = w[v * N + u] = (uint16_t)(w[u * N + v] + 7);
}

/* Bug 01 lives here: one SPF per change instead of one SPF for the whole event. */
NOINLINE static void compute_routes(void) {
  for (int i = 0; i < C.changes; i++) {
    apply_change(i);
    if (C.spf_per_change) spf_run();
  }
  if (!C.spf_per_change) spf_run();
}

NOINLINE static void rib_update(void) {
  rib_lock_acquire();
  for (int i = 0; i < R; i++) {
    int node = i / PREFIXES_PER_NODE;
    rib[i].nexthop = firsthop[node];
    rib[i].metric = dist[node];
  }
  rib_lock_release();
}

/* Lab 04: someone lowered the pipeline threads' priority "to protect the I/O pollers".
 * On Linux, setpriority() on a thread id changes just that thread. Raising nice needs no privilege. */
static void set_nice(void) {
  if (C.pipeline_nice) setpriority(PRIO_PROCESS, (id_t)gettid(), C.pipeline_nice);
}

/* ---------- per-thread schedstat (lab 04) ---------- */
static char tnames[64][16];
static unsigned long long t_run[64], t_wait[64];
static int ntids;
static pthread_mutex_t track_mu = PTHREAD_MUTEX_INITIALIZER;

/* Each thread reads its own schedstat just before it exits: on-CPU ns, run-queue wait ns. */
static void schedstat_self(const char *name) {
  if (!C.schedstat) return;
  unsigned long long run = 0, wait = 0;
  FILE *f = fopen("/proc/thread-self/schedstat", "r");
  if (f) { if (fscanf(f, "%llu %llu", &run, &wait) != 2) run = wait = 0; fclose(f); }
  pthread_mutex_lock(&track_mu);
  if (ntids < 64) {
    snprintf(tnames[ntids], sizeof tnames[0], "%s", name);
    t_run[ntids] = run;
    t_wait[ntids] = wait;
    ntids++;
  }
  pthread_mutex_unlock(&track_mu);
}

/* ---------- the "show rib" walker and its slow terminal (lab 02) ---------- */
static int term_fd[2];
static pthread_mutex_t walk_mu = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t walk_cv = PTHREAD_COND_INITIALIZER;
static int walk_go;

NOINLINE static void cli_format_and_write(const struct route *r, int n) {
  char line[96];
  for (int i = 0; i < n; i++) {
    int len = snprintf(line, sizeof line, "%u.%u.%u.0/24 via node %u metric %u\n",
                       r[i].prefix >> 24, (r[i].prefix >> 16) & 255, (r[i].prefix >> 8) & 255,
                       r[i].nexthop, r[i].metric);
    if (write(term_fd[1], line, (size_t)len) < 0) return;
  }
}

/* Bug 02 lives here: holding rib_lock while writing to a slow reader. */
NOINLINE static void cli_show_rib(void) {
  if (C.walk_holds_lock) {
    rib_lock_acquire();
    cli_format_and_write(rib, R);
    rib_lock_release();
  } else {
    struct route *snap = malloc(R * sizeof *snap);
    rib_lock_acquire();
    memcpy(snap, rib, R * sizeof *snap);
    rib_lock_release();
    cli_format_and_write(snap, R);
    free(snap);
  }
}

static void *cli_main(void *arg) {
  (void)arg;
  pthread_setname_np(pthread_self(), "pktd-cli");
  pthread_mutex_lock(&walk_mu);
  while (!walk_go) pthread_cond_wait(&walk_cv, &walk_mu);
  pthread_mutex_unlock(&walk_mu);
  cli_show_rib();
  close(term_fd[1]);
  return NULL;
}

/* ---------- the SPF throttle (lab 05) ---------- */
static uint64_t thr_last_ns;
static int thr_hold_ms = HOLD_INIT_MS;

static void throttle_history(void) {
  /* The link flapped C.flaps times ten minutes ago; each flap doubled the hold. */
  for (int i = 0; i < C.flaps; i++) thr_hold_ms = thr_hold_ms * 2 > HOLD_MAX_MS ? HOLD_MAX_MS : thr_hold_ms * 2;
  thr_last_ns = now_ns() - 600ull * 1000000000ull;
}

/* Bug 05 lives here: the backoff never resets after the network goes quiet. */
NOINLINE static void throttle_wait(void) {
  uint64_t t = now_ns();
  if (C.hold_reset && t - thr_last_ns > QUIET_RESET_S * 1000000000ull) thr_hold_ms = HOLD_INIT_MS;
  thr_last_ns = t;
  int hold = thr_hold_ms;
  DTRACE_PROBE1(pktd, hold, hold);
  struct timespec ts = { hold / 1000, (long)(hold % 1000) * 1000000L };
  clock_nanosleep(CLOCK_MONOTONIC, 0, &ts, NULL);
  thr_hold_ms = hold * 2 > HOLD_MAX_MS ? HOLD_MAX_MS : hold * 2;
}

/* ---------- I/O pollers (lab 04) ---------- */
static atomic_int stop_all;
static atomic_int io_ready;
static pthread_mutex_t io_mu = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t io_cv = PTHREAD_COND_INITIALIZER;

/* Bug 04 lives here: spinning on a flag instead of sleeping until there is work. */
NOINLINE static void io_poll_once(void) {
  if (C.poll_busy) {
    for (int i = 0; i < 1000 && !atomic_load(&io_ready); i++) __asm__ volatile("pause");
  } else {
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    ts.tv_nsec += 10000000;
    if (ts.tv_nsec >= 1000000000) { ts.tv_sec++; ts.tv_nsec -= 1000000000; }
    pthread_mutex_lock(&io_mu);
    if (!atomic_load(&io_ready) && !atomic_load(&stop_all)) pthread_cond_timedwait(&io_cv, &io_mu, &ts);
    pthread_mutex_unlock(&io_mu);
  }
}

static void *poller_main(void *arg) {
  char name[16];
  snprintf(name, sizeof name, "pktd-io%ld", (long)(intptr_t)arg);
  pthread_setname_np(pthread_self(), name);
  while (!atomic_load(&stop_all)) io_poll_once();
  schedstat_self(name);
  return NULL;
}

/* ---------- push and FIB ---------- */
static int fib_fd[2];
static struct route *fib;

/* Bug 03 lives here: batch == 1 means one message and one ack per route. */
NOINLINE static void push_routes(void) {
  int batch = C.stop_and_wait ? 1 : BATCH;
  uint32_t ack;
  for (int i = 0; i < R; i += batch) {
    int n = R - i < batch ? R - i : batch;
    if (write(fib_fd[0], &rib[i], (size_t)n * sizeof *rib) < 0) { perror("push write"); exit(1); }
    if (read(fib_fd[0], &ack, sizeof ack) != sizeof ack) { perror("push ack"); exit(1); }
  }
}

static void *fib_main(void *arg) {
  (void)arg;
  pthread_setname_np(pthread_self(), "pktd-fib");
  set_nice();
  static struct route buf[BATCH];
  int have = 0;
  for (;;) {
    ssize_t got = read(fib_fd[1], buf, sizeof buf);
    if (got <= 0) break;
    int n = (int)(got / (ssize_t)sizeof *buf);
    memcpy(&fib[have], buf, (size_t)n * sizeof *buf);
    have += n;
    uint32_t ack = (uint32_t)have;
    if (write(fib_fd[1], &ack, sizeof ack) != sizeof ack) break;
  }
  schedstat_self("pktd-fib");
  return NULL;
}

/* ---------- threads that carry the event ---------- */
static pthread_mutex_t ev_mu = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t ev_cv = PTHREAD_COND_INITIALIZER;
static int ev_fired, rib_done;
static void *spf_main(void *arg) {
  (void)arg;
  pthread_setname_np(pthread_self(), "pktd-spf");
  set_nice();
  pthread_mutex_lock(&ev_mu);
  while (!ev_fired) pthread_cond_wait(&ev_cv, &ev_mu);
  pthread_mutex_unlock(&ev_mu);

  tl_begin(ST_HOLD);
  throttle_wait();
  tl_end(ST_HOLD);

  tl_begin(ST_COMPUTE);
  if (C.cli_walk) {
    pthread_mutex_lock(&walk_mu);
    walk_go = 1;
    pthread_cond_signal(&walk_cv);
    pthread_mutex_unlock(&walk_mu);
  }
  compute_routes();
  tl_end(ST_COMPUTE);

  tl_begin(ST_RIB);
  rib_update();
  tl_end(ST_RIB);

  pthread_mutex_lock(&ev_mu);
  rib_done = 1;
  pthread_cond_broadcast(&ev_cv);
  pthread_mutex_unlock(&ev_mu);
  schedstat_self("pktd-spf");
  return NULL;
}

static void *push_main(void *arg) {
  (void)arg;
  pthread_setname_np(pthread_self(), "pktd-push");
  set_nice();
  pthread_mutex_lock(&ev_mu);
  while (!rib_done) pthread_cond_wait(&ev_cv, &ev_mu);
  pthread_mutex_unlock(&ev_mu);
  tl_begin(ST_PUSH);
  push_routes();
  tl_end(ST_PUSH);
  schedstat_self("pktd-push");
  return NULL;
}

static void pin_cpus(int n) {
  cpu_set_t all, pick;
  CPU_ZERO(&pick);
  if (sched_getaffinity(0, sizeof all, &all) != 0) return;
  for (int c = CPU_SETSIZE - 1, got = 0; c >= 0 && got < n; c--)
    if (CPU_ISSET(c, &all)) { CPU_SET(c, &pick); got++; }
  sched_setaffinity(0, sizeof pick, &pick);
}

static void print_schedstat(void) {
  printf("\nschedstat  thread       on-cpu ms  runq-wait ms\n");
  for (int i = 0; i < ntids; i++)
    printf("schedstat  %-12s %9.1f %13.1f\n", tnames[i], t_run[i] / 1e6, t_wait[i] / 1e6);
}

static void print_timeline(void) {
  uint64_t conv = st_end[ST_PUSH];
  double total = ms(t0_ns, conv);
  printf("pktd route pipeline  lab=%s variant=%s  nodes=%d routes=%d changes=%d\n",
         C.lab, C.fixed ? "fixed" : "before", N, R, C.changes);
  printf("T+%10.3f ms  event      link change injected\n", 0.0);
  for (int s = 0; s < ST_N; s++) {
    printf("T+%10.3f ms  %-9s  begin\n", ms(t0_ns, st_begin[s]), stage_name[s]);
    printf("T+%10.3f ms  %-9s  end\n", ms(t0_ns, st_end[s]), stage_name[s]);
  }
  double handoff = ms(t0_ns, st_begin[ST_HOLD]) + ms(st_end[ST_HOLD], st_begin[ST_COMPUTE])
                 + ms(st_end[ST_COMPUTE], st_begin[ST_RIB]) + ms(st_end[ST_RIB], st_begin[ST_PUSH]);
  printf("\nbudget  stage      ms        share\n");
  for (int s = 0; s < ST_N; s++) {
    double d = ms(st_begin[s], st_end[s]);
    printf("budget  %-9s %9.3f  %5.1f%%\n", stage_name[s], d, 100.0 * d / total);
  }
  printf("budget  %-9s %9.3f  %5.1f%%\n", "handoff", handoff, 100.0 * handoff / total);
  printf("converged_ms=%.3f\n", total);
}

/* A tracer in a container knows this process only by its host PID, so it cannot read our
 * /proc/<pid>/maps to symbolize user stacks. PKTD_MAPS=<file> saves a copy for symbolize.py. */
static void save_maps(void) {
  const char *path = getenv("PKTD_MAPS");
  if (!path) return;
  FILE *in = fopen("/proc/self/maps", "r"), *out = fopen(path, "w");
  char line[512];
  while (in && out && fgets(line, sizeof line, in)) fputs(line, out);
  if (in) fclose(in);
  if (out) fclose(out);
}

/* Start a thread that already has its name: a new thread inherits its creator's name, and some
 * tools (perf trace) keep the name they saw first. So the creator wears the name for a moment.
 * A pipeline thread that fails to start would leave the others waiting for ever: stop instead. */
static void start_thread(pthread_t *t, void *(*fn)(void *), void *arg, const char *name) {
  pthread_setname_np(pthread_self(), name);
  int err = pthread_create(t, NULL, fn, arg);
  pthread_setname_np(pthread_self(), "pktd-ctl");
  if (err) { fprintf(stderr, "pthread_create: %s\n", strerror(err)); exit(1); }
}

/* Run one convergence event with the given configuration. */
static int pipeline_main(const struct cfg *cfg) {
  C = *cfg;
  N = C.nodes;
  R = N * PREFIXES_PER_NODE;
  if (C.cpus) pin_cpus(C.cpus);
  pthread_setname_np(pthread_self(), "pktd-ctl");
  topo_build();
  for (int i = 0; i < C.changes; i++) {
    changed_u[i] = (int)(rnd() % N);
    changed_v[i] = (changed_u[i] + 1 + (int)(rnd() % (N - 1))) % N;
  }
  spf_run(); /* initial convergence, not measured */
  throttle_history();
  fib = calloc(R, sizeof *fib);
  if (socketpair(AF_UNIX, SOCK_SEQPACKET, 0, fib_fd) != 0) { perror("socketpair"); return 1; }
  int sz = 1 << 20;
  setsockopt(fib_fd[0], SOL_SOCKET, SO_SNDBUF, &sz, sizeof sz);

  pthread_t spf, push, fibt, cli, term, poll[32];
  start_thread(&fibt, fib_main, NULL, "pktd-fib");
  start_thread(&spf, spf_main, NULL, "pktd-spf");
  start_thread(&push, push_main, NULL, "pktd-push");
  if (C.cli_walk) {
    if (pipe(term_fd) != 0) { perror("pipe"); return 1; }
    start_thread(&cli, cli_main, NULL, "pktd-cli");
    start_thread(&term, term_main, NULL, "pktd-term");
  }
  for (int i = 0; i < C.pollers && i < 32; i++) {
    char name[16];
    snprintf(name, sizeof name, "pktd-io%d", i);
    start_thread(&poll[i], poller_main, (void *)(intptr_t)i, name);
  }
  usleep(100000); /* let every thread reach its wait */

  pthread_mutex_lock(&ev_mu);
  t0_ns = now_ns();
  DTRACE_PROBE(pktd, event);
  ev_fired = 1;
  pthread_cond_broadcast(&ev_cv);
  pthread_mutex_unlock(&ev_mu);

  pthread_join(spf, NULL);
  pthread_join(push, NULL);
  DTRACE_PROBE(pktd, converged);
  atomic_store(&stop_all, 1);
  pthread_mutex_lock(&io_mu);
  pthread_cond_broadcast(&io_cv);
  pthread_mutex_unlock(&io_mu);
  for (int i = 0; i < C.pollers && i < 32; i++) pthread_join(poll[i], NULL);
  shutdown(fib_fd[0], SHUT_WR);
  pthread_join(fibt, NULL);
  if (C.cli_walk) { pthread_join(cli, NULL); pthread_join(term, NULL); }
  print_timeline();
  if (C.schedstat) print_schedstat();
  save_maps();
  return 0;
}

__attribute__((unused)) static int arg_fixed(int argc, char **argv) {
  for (int i = 1; i < argc; i++) if (strcmp(argv[i], "--fixed") == 0) return 1;
  return 0;
}
f1-where-time-goes.c
/* f1-where-time-goes.c — where a thread's wall time goes.
 *   spin   always on a CPU
 *   sleep  blocked in clock_nanosleep for 1 s (off-CPU)
 *   lock   blocked on a mutex another thread holds for 900 ms, then 100 ms of work
 *   q0-q2  three spinners pinned to one CPU: runnable, but mostly waiting in the run queue
 * Each thread reads its own schedstat (on-CPU ns, run-queue wait ns) before it exits;
 * whatever is left of its wall time was spent blocked (off-CPU). */
#define _GNU_SOURCE
#include <pthread.h>
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

static pthread_mutex_t mu = PTHREAD_MUTEX_INITIALIZER;
static pthread_mutex_t out = PTHREAD_MUTEX_INITIALIZER;
static int qn;

static double now_s(clockid_t c) {
  struct timespec ts;
  clock_gettime(c, &ts);
  return ts.tv_sec + ts.tv_nsec / 1e9;
}

static void report(const char *name, double t_start) {
  double wall = now_s(CLOCK_MONOTONIC) - t_start;
  unsigned long long run = 0, wait = 0;
  FILE *f = fopen("/proc/thread-self/schedstat", "r");
  if (f) { if (fscanf(f, "%llu %llu", &run, &wait) != 2) run = wait = 0; fclose(f); }
  double off = wall * 1e3 - run / 1e6 - wait / 1e6;
  pthread_mutex_lock(&out);
  printf("%-6s wall %5.0f ms = on-cpu %5.0f + runq-wait %5.0f + off-cpu %5.0f\n", name,
         wall * 1e3, run / 1e6, wait / 1e6, off < 0 ? 0 : off);
  pthread_mutex_unlock(&out);
}

/* Burn this thread's own CPU time, not wall time: on a shared CPU this takes longer. */
static void burn_cpu(double s) {
  double end = now_s(CLOCK_THREAD_CPUTIME_ID) + s;
  while (now_s(CLOCK_THREAD_CPUTIME_ID) < end) ;
}

static void *t_spin(void *a) {
  (void)a;
  double t = now_s(CLOCK_MONOTONIC);
  burn_cpu(1.0);
  report("spin", t);
  return NULL;
}

static void *t_sleep(void *a) {
  (void)a;
  double t = now_s(CLOCK_MONOTONIC);
  struct timespec ts = { 1, 0 };
  clock_nanosleep(CLOCK_MONOTONIC, 0, &ts, NULL);
  report("sleep", t);
  return NULL;
}

static void *t_holder(void *a) {
  (void)a;
  pthread_mutex_lock(&mu);
  usleep(900000);
  pthread_mutex_unlock(&mu);
  return NULL;
}

static void *t_lock(void *a) {
  (void)a;
  usleep(1000); /* let the holder take the lock first */
  double t = now_s(CLOCK_MONOTONIC);
  pthread_mutex_lock(&mu);
  pthread_mutex_unlock(&mu);
  burn_cpu(0.1);
  report("lock", t);
  return NULL;
}

static void *t_queue(void *a) {
  cpu_set_t one;
  CPU_ZERO(&one);
  CPU_SET((int)(long)a, &one);
  pthread_setaffinity_np(pthread_self(), sizeof one, &one);
  double t = now_s(CLOCK_MONOTONIC);
  burn_cpu(0.333);
  char name[8];
  pthread_mutex_lock(&out);
  snprintf(name, sizeof name, "q%d", qn++);
  pthread_mutex_unlock(&out);
  report(name, t);
  return NULL;
}

static void start(pthread_t *t, void *(*fn)(void *), void *arg) {
  int err = pthread_create(t, NULL, fn, arg);
  if (err) { fprintf(stderr, "pthread_create: %s\n", strerror(err)); exit(1); }
}

int main(void) {
  cpu_set_t all;
  long cpu = 0;
  sched_getaffinity(0, sizeof all, &all);
  for (int c = CPU_SETSIZE - 1; c >= 0; c--) if (CPU_ISSET(c, &all)) { cpu = c; break; }
  pthread_t t[7];
  start(&t[0], t_spin, NULL);
  start(&t[1], t_sleep, NULL);
  start(&t[2], t_holder, NULL);
  start(&t[3], t_lock, NULL);
  for (int i = 0; i < 3; i++) start(&t[4 + i], t_queue, (void *)cpu);
  for (int i = 0; i < 7; i++) pthread_join(t[i], NULL);
  return 0;
}

 *   ./06-boss                      nothing fixed
 *   ./06-boss --fix=push,lock      fix some of them (any of: hot, lock, push, hold, all)

static int has(const char *list, const char *w) {
  if (!list) return 0;
  size_t n = strlen(w);
  for (const char *p = list; *p; ) {
    const char *e = strchr(p, ',');
    size_t len = e ? (size_t)(e - p) : strlen(p);
    if ((len == n && strncmp(p, w, n) == 0) || (len == 3 && strncmp(p, "all", 3) == 0)) return 1;
    if (!e) break;
    p = e + 1;
  }
  return 0;
}

int main(int argc, char **argv) {
  const char *fix = NULL;
  for (int i = 1; i < argc; i++) if (strncmp(argv[i], "--fix=", 6) == 0) fix = argv[i] + 6;
  struct cfg c = { .lab = "06-boss", .fixed = fix != NULL, .nodes = 1500, .changes = 48,
                   .spf_per_change = !has(fix, "hot"),
                   .cli_walk = 1, .walk_holds_lock = !has(fix, "lock"),
                   .stop_and_wait = !has(fix, "push"),
                   .flaps = 2, .hold_reset = has(fix, "hold") };
  if (fix) printf("fixes applied: %s\n", fix);
  return pipeline_main(&c);
}

// offcpu.bt — blocked (off-CPU) time by thread and user stack, between the event and convergence.
//   PKTD_MAPS=/tmp/maps bpftrace -c ./02-lock bt/offcpu.bt ./02-lock     ($1 = the lab binary)
// Blocked time runs from the switch-out to the wake-up: the run-queue wait after the wake-up is
// runqlat.bt's, not this script's.
// Scope: sched tracepoints fire for every thread on the host. A switch-out runs in the outgoing
// task, so `cgroup` identifies it: only pktd- threads in this container's cgroup are recorded,
// and wake-ups are matched against those thread ids. Armed by pktd's own USDT probes; exits at
// convergence. Output is microseconds per (thread, stack); symbolize.py names the frames
// (PKTD_MAPS saves the lab's memory map for it) and fold-bt.awk turns it into folded stacks.

usdt:$1:pktd:event { @armed = 1; }
usdt:$1:pktd:converged { exit(); }

// Going to sleep: remember when, and where in user space. A thread switched out while still
// runnable (prev_state 0, or 0x100 for a preemption inside the kernel) isn't blocked.
tracepoint:sched:sched_switch
/@armed && cgroup == cgroupid("/sys/fs/cgroup") && strncmp(args->prev_comm, "pktd-", 5) == 0 &&
 args->prev_state != 0 && args->prev_state != 0x100/ {
  @start[args->prev_pid] = nsecs;
  @stack[args->prev_pid] = ustack(perf);
  @name[args->prev_pid] = args->prev_comm;
}

// Woken: charge the blocked time to the stack it went to sleep from.
tracepoint:sched:sched_wakeup /@start[args->pid]/ {
  @offcpu_us[@name[args->pid], @stack[args->pid]] = sum((nsecs - @start[args->pid]) / 1000);
  delete(@start[args->pid]);
  delete(@stack[args->pid]);
  delete(@name[args->pid]);
}

END { clear(@start); clear(@stack); clear(@name); delete(@armed); }

// runqlat.bt — run-queue latency of pktd threads: time from "ready to run" to "running".
//   bpftrace -c ./04-sched bt/runqlat.bt ./04-sched              ($1 = the lab binary)
// A thread becomes ready when it is woken, or when it is preempted while still runnable.
// Scope: sched tracepoints fire host-wide. `cgroup` is the cgroup of the task running when the
// event fires, so it identifies our threads only on the switch-out side (the event runs in the
// outgoing task). Our thread ids are recorded there, filtered on this container's cgroup and the
// pktd- names; wake-ups and switch-ins are then matched against that set.

tracepoint:sched:sched_switch
/cgroup == cgroupid("/sys/fs/cgroup") && strncmp(args->prev_comm, "pktd-", 5) == 0/ {
  @ours[args->prev_pid] = 1;   // every pktd thread blocks once before the event, so it is known

usdt:$1:pktd:converged { exit(); }

tracepoint:sched:sched_wakeup_new
/@armed && @ours[args->pid]/ {
  @ready[args->pid] = nsecs;
}

tracepoint:sched:sched_switch
/@armed && (@ours[args->prev_pid] || @ours[args->next_pid])/ {
  // Preempted while runnable, so straight back to waiting in the queue: prev_state is 0
  // (TASK_RUNNING), or 0x100 when the preemption happened inside the kernel.
  if ((args->prev_state == 0 || args->prev_state == 0x100) && @ours[args->prev_pid]) {
    @ready[args->prev_pid] = nsecs;
  }
  $r = @ready[args->next_pid];
  if ($r) {
    if (strncmp(args->next_comm, "pktd-io", 7) == 0) {
      @runq_us["pktd-io*"] = hist((nsecs - $r) / 1000);
    } else {
      @runq_us[args->next_comm] = hist((nsecs - $r) / 1000);
      @runq_total_us[args->next_comm] = sum((nsecs - $r) / 1000);
    }
    delete(@ready[args->next_pid]);
  }
}

END { clear(@ready); clear(@ours); delete(@armed); }

fold-perf.awk
# fold-perf.awk — perf script output -> folded stacks ("comm;outer;...;leaf count").
#   perf script -F comm,ip,sym | awk -f fold-perf.awk
# perf script prints each sample as a header line (the comm), then one indented line per frame,
# leaf first, then a blank line. Offsets (+0x1f) are dropped so samples in one function merge.
# A run of unresolvable frames (a stack walk that went astray in code without frame pointers)
# is kept as one "[unknown]", so it can't stack a hundred empty rows onto a flame graph.
function flush(   i, s) {
  if (comm == "") return
  s = comm
  for (i = n; i >= 1; i--) s = s ";" f[i]
  count[s]++
  comm = ""; n = 0
}
/^[ \t]*$/ { flush(); next }
/^[ \t]/   { sym = $2; sub(/\+0x[0-9a-f]+$/, "", sym)
             if (!(sym == "[unknown]" && n > 0 && f[n] == "[unknown]")) f[++n] = sym
             next }
           { flush(); comm = $1; n = 0 }
END {
  flush()
  for (s in count) print s, count[s] | "sort"
}

#!/usr/bin/env python3
"""symbolize.py MAPS — put function names on the user-space frames in bpftrace output.

bpftrace prints ustack(perf) frames as "<hex-address> <symbol> (<path>)". Inside a container it
knows the traced thread only by its host PID, which does not exist in the container's /proc, so
every frame comes out as "[unknown]". The lab saves its own /proc/self/maps (PKTD_MAPS=<file>);
this script maps each address to a file offset, converts it to the ELF virtual address with the
file's LOAD segments (readelf -lW), and asks addr2line for the function.
Reads bpftrace output on stdin, writes it to stdout with frames rewritten as
"<hex-address> <function> (<path>)"; every other line passes through unchanged.
"""
import re
import subprocess
import sys

FRAME = re.compile(r'^(\s+)([0-9a-f]{6,16}) .*$')


def load_maps(path):
    maps = []
    with open(path) as f:
        for line in f:
            p = line.split()
            if len(p) >= 6 and 'x' in p[1] and p[5].startswith('/'):
                lo, hi = (int(x, 16) for x in p[0].split('-'))
                maps.append((lo, hi, int(p[2], 16), p[5]))
    return maps


def load_segments(path):
    """(p_offset, p_vaddr, p_filesz) of each LOAD segment, from readelf -lW."""
    out = subprocess.run(['readelf', '-lW', path], capture_output=True, text=True).stdout
    segs = []
    for line in out.splitlines():
        p = line.split()
        if p and p[0] == 'LOAD':
            segs.append((int(p[1], 16), int(p[2], 16), int(p[4], 16)))
    return segs


def to_vaddr(segs, off):
    """addr2line wants the ELF virtual address; the maps give a file offset."""
    for p_off, p_vaddr, p_filesz in segs:
        if p_off <= off < p_off + p_filesz:
            return off - p_off + p_vaddr
    return off


def main():
    maps = load_maps(sys.argv[1])
    text = sys.stdin.read().splitlines()
    wanted = {}  # path -> set of file offsets
    where = {}   # line number -> (path, offset)
    first = True  # the first frame of a stack is the exact instruction pointer
    for n, line in enumerate(text):
        m = FRAME.match(line)
        if not m:
            first = True
            continue
        addr = int(m.group(2), 16)
        # Every frame but the first is a return address, which points just past its call
        # instruction; look up the call itself, or a call at a function's end names the next one.
        adj = 0 if first else 1
        first = False
        for lo, hi, off, path in maps:
            if lo <= addr < hi:
                where[n] = (path, addr - lo + off - adj)
                wanted.setdefault(path, set()).add(addr - lo + off - adj)
                break
    names = {}
    for path, offs in wanted.items():
        offs = sorted(offs)
        segs = load_segments(path)
        out = subprocess.run(['addr2line', '-f', '-e', path] + [hex(to_vaddr(segs, o)) for o in offs],
                             capture_output=True, text=True).stdout.splitlines()
        for i, o in enumerate(offs):
            fn = out[2 * i] if 2 * i < len(out) else '??'
            names[(path, o)] = '[unknown]' if fn == '??' else fn
    for n, line in enumerate(text):
        m = FRAME.match(line)
        if m and n in where:
            path, o = where[n]
            line = f'{m.group(1)}{m.group(2)} {names[(path, o)]} ({path})'
        print(line)


if __name__ == '__main__':
    main()

run-capture.sh
#!/bin/bash
# run-capture.sh — run rows of captures.tsv and write captures/<id>.txt (inside the ptg-lab container).
# usage: ./run-capture.sh [id ...]        (no ids = every row)
#
# Each capture file is:
#   # src <file> <sha256>     one line per source listed in the row ("-" = none)
#   # cmd <command>
#   <combined stdout+stderr of the command>
# C0 control bytes other than \t \n \r are stripped, so ANSI colour and stray
# binary bytes never reach the guide. The command's exit status is ignored:
# check.sh decides whether a capture is good.
set -u
cd "$(dirname "$0")" || exit 2

TSV=captures.tsv
TIMEOUT=${CAP_TIMEOUT:-300}   # seconds per capture, so a hung lab cannot stall a run

rows() { grep -v -e '^#' -e '^[[:space:]]*$' "$TSV"; }

# Reject unknown ids before running anything.
for want in "$@"; do
  rows | cut -f1 | grep -qxF -- "$want" || { echo "run-capture: unknown id: $want" >&2; exit 2; }
done

mkdir -p captures
while IFS=$'\t' read -r id srcs cmd; do
  if [ $# -gt 0 ]; then
    hit=0; for want in "$@"; do [ "$want" = "$id" ] && hit=1; done
    [ $hit -eq 1 ] || continue
  fi
  out=captures/$id.txt
  if [ "$srcs" != "-" ]; then
    IFS=',' read -ra files <<< "$srcs"
    for f in "${files[@]}"; do
      [ -f "$f" ] || { echo "run-capture: $id: source not found: $f" >&2; exit 2; }
    done
  fi
  {
    if [ "$srcs" != "-" ]; then
      IFS=',' read -ra files <<< "$srcs"
      for f in "${files[@]}"; do
        echo "# src $f $(sha256sum "$f" | cut -d' ' -f1)"
      done
    fi
    echo "# cmd $cmd"
    timeout -k 5 "$TIMEOUT" bash -c "$cmd" < /dev/null 2>&1 | tr -d '\000-\010\013\014\016-\037'
  } > "$out" || exit 2
  echo "captured $id"
done < <(rows)
check.sh
#!/bin/bash
# check.sh — match captures/<id>.txt against expect.tsv (inside the ptg-lab container).
# usage: ./check.sh [id ...]              (no ids = every id in expect.tsv)
# Prints PASS <id> or FAIL <id>: <reason> per id; exits 1 on any miss.
# Regexes are POSIX ERE and see only the capture body, never the # src / # cmd header.
set -u
cd "$(dirname "$0")" || exit 2

TSV=expect.tsv
exp() { grep -v -e '^#' -e '^[[:space:]]*$' "$TSV"; }

if [ $# -eq 0 ]; then
  ids=()  # bash 3.2 (macOS) has no mapfile
  while IFS= read -r id; do ids+=("$id"); done < <(exp | cut -f1 | awk '!seen[$0]++')
else
  ids=("$@")
fi

rc=0
for id in ${ids[@]+"${ids[@]}"}; do
  f=captures/$id.txt
  if [ ! -f "$f" ]; then echo "FAIL $id: no captures/$id.txt"; rc=1; continue; fi
  body=$(awk 'h && /^# (src|cmd) /{next} {h=0; print}' h=1 "$f")
  n=0; miss=0
  while IFS=$'\t' read -r eid re; do
    [ "$eid" = "$id" ] || continue
    n=$((n + 1))
    printf '%s\n' "$body" | grep -Eq -- "$re" || { echo "FAIL $id: missing /$re/"; miss=1; }
  done < <(exp)
  if [ $n -eq 0 ]; then echo "FAIL $id: no expectations in $TSV"; miss=1; fi
  if [ $miss -eq 0 ]; then echo "PASS $id"; else rc=1; fi
done
exit $rc
remote.sh
#!/usr/bin/env bash
# remote.sh — run lab captures on a remote x86-64 Linux Docker host. Runs on your workstation.
# usage: LAB_HOST=user@host ./remote.sh [capture-id ...]   (no ids = every row of captures.tsv)
#        CAP_TIMEOUT=<s> raises run-capture.sh's per-capture timeout (default 300 s)
#        LAB_HOST=user@host ./remote.sh --probe            (which perf / eBPF features work there)
#
# Capture run, in order:
#   1. rsync this directory to ~/ptg-lab/ on the host
#   2. docker build -t ptg-lab (the Dockerfile copies nothing, so no build context is sent)
#   3. run-capture.sh <ids> && check.sh <ids> in the container
#   4. chown /lab back to the host user (uid/gid expanded by the host's shell)
#   5. rsync captures/ back
#   6. leak-gate.sh over every capture, here (the container has no repo, git or term list)
# Only the host's sudo-free Docker is used; nothing on the host is reconfigured. The container
# flags (see README.md) let perf and bpftrace observe this container's own processes.
set -euo pipefail
: "${LAB_HOST:?set LAB_HOST=user@host}"
cd "$(dirname "$0")"

SSH=(ssh -o BatchMode=yes)
RSH="ssh -o BatchMode=yes"
RDIR=ptg-lab
# Expanded by the host's shell after "cd ptg-lab", so $PWD is the host's lab copy.
BASE='--rm --hostname pktd-lab -v "$PWD":/lab -w /lab -v /sys/kernel/tracing:/sys/kernel/tracing:ro --ulimit memlock=-1 --cap-add SYS_ADMIN --cap-add SYSLOG'
LABS='f1-where-time-goes 00-baseline 01-hot-path 02-lock 03-syscalls 04-sched 05-throttle 06-boss'
# Built binaries and perf data live only on the host: never uploaded, never deleted by --delete.
KEEP=(--exclude 'perf.data*' --exclude '.*.sh')
for l in $LABS; do KEEP+=(--exclude "/$l"); done

up()    { rsync -az --delete -e "$RSH" "${KEEP[@]}" ./ "$LAB_HOST:$RDIR/"; }
build() { "${SSH[@]}" "$LAB_HOST" "cd $RDIR && docker build -q -t ptg-lab - < Dockerfile"; }

if [ "${1:-}" = "--probe" ]; then
  up; build
  "${SSH[@]}" "$LAB_HOST" "cd $RDIR && docker run $BASE ptg-lab ./probe.sh"
  exit 0
fi

for id in "$@"; do
  [[ $id =~ ^[A-Za-z0-9._-]+$ ]] || { echo "remote.sh: bad capture id: $id" >&2; exit 2; }
done
ids="$*"
if [ -n "${CAP_TIMEOUT:-}" ]; then
  [[ $CAP_TIMEOUT =~ ^[1-9][0-9]*$ ]] || { echo "remote.sh: CAP_TIMEOUT must be a positive integer (seconds), got: $CAP_TIMEOUT" >&2; exit 2; }
fi

up; build
set +e
"${SSH[@]}" "$LAB_HOST" "cd $RDIR && docker run $BASE ${CAP_TIMEOUT:+-e CAP_TIMEOUT=$CAP_TIMEOUT} ptg-lab bash -c './run-capture.sh $ids && ./check.sh $ids'"
run_rc=$?
"${SSH[@]}" "$LAB_HOST" 'cd ptg-lab && docker run --rm -v "$PWD":/lab ptg-lab chown -R "$(id -u):$(id -g)" /lab'
set -e
mkdir -p captures
rsync -az -e "$RSH" "$LAB_HOST:$RDIR/captures/" captures/

gate=$(git rev-parse --show-toplevel)/scripts/leak-gate.sh
set +e
"$gate" captures/*.txt
leak_rc=$?
set -e
[ $leak_rc -eq 0 ] || { echo "remote.sh: leak gate failed (exit $leak_rc)" >&2; exit 1; }
exit $run_rc
